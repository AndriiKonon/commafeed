**1 Quarkus та особливості розробки**

**Принцип Build Time:** Quarkus переносить сканування класів, конфігурацію та перевірки з runtime на етап компіляції (build time), що забезпечує ультрашвидкий запуск і мінімальне споживання пам'яті.
**Сфера застосування:** Оптимізований для контейнерів (Docker, Kubernetes) та безсерверних (Serverless) середовищ.
**REST-анотації:**
  **@Path("/...")** — задає URL-шлях ендпоінту.
  **@GET** — вказує обробку HTTP-методу GET.
**Dev Mode:** Режим гарячого перезавантаження коду (`mvnw -pl commafeed-server quarkus:dev`), який автоматично відстежує зміни коду та проганяє тести у фоні.

**2 Веб-технології: RSS та REST**

**RSS:** XML-стандарт для автоматичної публікації та агрегації оновлень із сайтів. CommaFeed завантажує ці XML-файли та збирає їх у єдину стрічку.
**REST API:** Архітектурний стиль взаємодії через HTTP, де дані розглядаються як ресурси за унікальними URL.
**HTTP-методи та коди:**
  **GET** — зчитування даних.
  **POST** — створення нового ресурсу (повертає статус `200 OK`).
  **DELETE** — видалення ресурсу.
**URL vs HTTP-метод:** URL вказує на конкретний ресурс (об'єкт), а HTTP-метод визначає дію над ним (метод класу).

**3 Maven та конфігурація pom.xml**

**pom.xml (Project Object Model):** Головний конфігураційний файл збірки (аналог `CMakeLists.txt` \+ package manager).

**dependency vs plugin:**
  **<dependency>** - зовнішня бібліотека, яка підключається до коду програми та автоматиччно завантажуться з `Maven Central`
  **<plugin>** - інструмент, що виконує конкретні задачі під час збірки(компіляція, форматування, генерація коду)

**Ієрархія POM:** Кореневий `pom.xml` керує модулями (`<modules>`), спільними версіями залежностей та плагінами для всього проекту; дочірні `pom.xml` містять специфічні налаштування окремих модулів

**4 Команди, прапорці та інструменти**

**mvn vs mvnw:** `mvn` — глобально встановлена версія; `mvnw` (Maven Wrapper) — проєктний скрипт, що фіксує точну версію Maven для всіх розробників.
**Фази збірки:**
  **clean** — видалення згенерованої папки `target/`.
  **compile** — компіляція коду в байт-код `.class`.
  **test** — проганяння автотестів.
  **package** — пакування коду у фінальний `.jar` файл.
  **install** — копіювання `.jar` у локальний репозиторій `~/.m2/repository/`.
**Прапорці CLI:**
  **e(--errors)** — виведення повного stack trace помилок.
  **pl(--projects)** — вказівка конкретного модуля для збірки.
  **am (--also-make )** — автоматична збірка всіх залежних модулів.
**Biome:** Надшвидкий інструмент форматування та лінтингу JS/TS/JSON/CSS коду, написаний на Rust (аналог `clang-format`).

**5 Залежності**

**Області видимості залежностей (Dependency Scopes):**
  **compile**: Потрібна на всіх етапах (компіляція, тести, виконання) і пакується у підсумковий `.jar`.
  **provided**: Потрібна лише для компіляції чи генерації коду (наприклад, Lombok) і **не пакується** у підсумковий бінарник.
  **test**: Використовується виключно для компіляції та запуску автотестів і під час релізу ігнорується.
**Транзитивні залежності (Transitive Dependencies):**
  Глибокі рівні вкладеності в `dependency:tree` — це «залежності - залежностей». Maven завантажує їх автоматично, тому у виводі з'являються бібліотеки, яких немає прямо у вашому `pom.xml.
